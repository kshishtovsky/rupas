# Rupas — All-in-One клиент обхода блокировок
## PRD v1.0 (на основе лабораторных данных 2025-10)
Детальный системный дизайн: docs/SYSTEM_DESIGN.md (ADR, горячий путь, алгоритмы, бюджеты, threat model).

---

## 1. Видение

Одна кнопка: клиент сам решает, какому пакету что сделать — модифицировать локально
(DPI-desync, без сервера, полная скорость) или завести в туннель (VLESS-Reality на VPS).
Пользователь не настраивает прокси нигде: ни в Telegram, ни в Discord, ни в браузере.

**Не-цели v1:** iOS/macOS, монетизация, мультипользовательский режим, сторы.

## 2. Лабораторный фундамент (данные, не гипотезs)

Домашний ISP (Ethernet, единственный стенд):

| Факт | Данные | Следствие |
|---|---|---|
| YouTube/Discord блокируются по SNI | timeout после ClientHello; IP не блокированы; github/vk/cloudflare проходят; no-SNI к YT-IP проходит | локальный desync достаточен, VPS не нужен |
| Рабочая стратегия | fake + TTL-фейки, окно TTL [12,∞), autottl не работает | нужна автокалибровка TTL (probe-engine) |
| Реальный браузер проходит | fake ttl=13: Chrome открывает YouTube, handshake 0.05s | стратегия подтверждена на живом трафике |
| curl/Schannel НЕ проходит | ECH-расширение → ТСПУ дропает; все стратегии мимо | probe-engine обязан слать browser-like CH; в репорты продукта — детект ECH-дропа |
| Telegram — IP-blackhole | SYN не проходит: все DC, порты 443/80/5222 (149.154.x, 91.108.x, 95.161.x) | desync бессилен; только туннель по CIDR/ASN |
| UDP-порты медиа мертвы | :53/:123 живы, :3478/:19302/:5353 дроп (RU+зарубеж) | голос Discord — только через туннель |
| QUIC UDP:443 | не измеряем без http3-клиента; браузер откатится на TCP | не блокер |
| Happ-конфликт | WFP-фильтр глушит UDP+TCP:53 на всех интерфейсах | детект WFP-конфликтов в клиенте обязателен |

## 3. User Stories

US-1 Пользователь жмёт одну кнопку. YouTube 4K играет на полной скорости канала.
US-2 Discord: текст/медиа/голос работают одновременно, голос без потерь.
US-3 Telegram работает без ввода прокси в самом TG. На ПК и Android.
US-4 При смене правил ТСПУ клиент сам перебирает стратегии (≤30 c) и молча чинится.
US-5 Встроенный прокси-сервер пользователя (VPS+Reality) подхватывается QR/ссылкой.
US-6 Лог/диагностика: одна кнопка «почему не работает» → текстовый отчёт.

## 4. Архитектура

Единый Go-процесс (кросс-платформенное ядро + платформенные слои).

    [WinDivert/wintun]        [netstack/gVisor]        [sing-box как lib]
           │                        │                        │
    ┌──────┴────────────────────────┴────────────────────────┴──────┐
    │                    RUPAS CORE (Go)                            │
    │  packet-inspector (SNI/CIDR/L7) → rule-engine → action:      │
    │     DESYNC(fake/split/disorder) | TUNNEL(vless) | DIRECT     │
    │  probe-engine (browser-like CH, TTL-калибровка, health)     │
    │  config (YAML: сервисы→правила, профили провайдеров)         │
    └──────────────────────────────────────────────────────────────┘

Компоненты:
- **packet-inspector**: разбор TCP/UDP потоков на лету (SNI, ALPN, L7 Discord/STUN).
- **desync-модуль** (пишем с нуля на Go, обвязка над WinDivert/windivert-go):
  fake (TTL-фейки из калибровки), split/multisplit, disorder. Конструктор фейковых
  CH из шаблонов (uTLS для реалистичности).
- **tunnel-core**: sing-box как библиотека (Go) — VLESS/Reality-клиент, XUDP для
  UDP-туннелирования, маршрутизация по правилам.
- **rule-engine**: таблица решений (см. §5), hot-reload.
- **probe-engine**: на старте и по расписанию/деградации: (а) классификация
  блокировки цели (SNI-drop/IP-drop/RST), (б) бинарный поиск TTL для фейков,
  (в) health-check туннеля (реальный handshake до VPS + маркерный HTTP-запрос).
  ⚠ Обязан слать browser-like ClientHello (uTLS + PQ key share) — лаборатория
  доказала, что «тощий» CH даёт ложноположительную калибровку.
- **WFP-детектор**: проверка чужих WFP-фильтров (Happ и пр.) — предупреждение
  «обнаружен конфликтующий VPN-клиент».

## 5. Таблица маршрутизации (текущая реализация, 2026-10-26)

Порядок разрешения фиксирован: **CIDR → SNI → ports → default** (§4.2 системного
дизайна). У правила опционально есть `proto` (`tcp`/`udp`/пусто = любой).

| Трафик | Условие | Действие |
|---|---|---|
| LAN (10/8, 172.16/12, 192.168/16, 169.254/16, multicast, broadcast) | — | DIRECT |
| Telegram CIDR (149.154.160.0/20, 91.108.0.0/16, 91.105.192.0/23 — медиа, 185.76.151.0/24 — медиа, 95.161.76.100/32) | любые порты | TUNNEL → VLESS-Reality |
| YouTube (www.youtube.com, youtube.com, *.youtube.com, *.googlevideo.com) | TCP:443 | DESYNC fake + калиброванный TTL |
| Discord (discord.com, updates.discord.com, gateway.discord.gg, discord.gg, *.discord.gg, discordapp.com/.net + поддомены) | TCP:443 | TUNNEL — Electron шлёт настоящий ECH |
| Discord voice UDP (50000–65535), STUN :3478 | UDP | TUNNEL → XUDP/Hysteria2 |
| RU-зоны (*.ru, *.su, *.xn--p1ai (.рф), .москва, .онлайн, .дети, .бел) | — | DIRECT |
| RU-сервисы на .com (vk.com, ok.ru, userapi.com + поддомены) | — | DIRECT — VPS-xray отказывает CONNECT к RU-IP |
| UDP:443 (QUIC) | — | BLOCK — ТСПУ чернодырит QUIC, браузер обязан уйти на TCP |
| DNS :53 | — | DIRECT (иначе рекурсия и весь резолв через VPS) |
| **всё остальное** | — | **TUNNEL** (политика владельца) |

Следствия режима «всё остальное → tunnel»:
- первое соединение с новым dst получает RST, клиент передиал-ит; новый SYN
  ловится fast-path'ом по кешу dst (60 с) и уходит в терминатор. Это +1 RTT
  однократно на адрес, для браузеров незаметно;
- не-TLS TCP (SSH и подобное) на незнакомые адреса остаётся DIRECT: вердикта без
  ClientHello нет. Известное ограничение v1;
- канал VPS становится потолком для всего незнаемого трафика (RU-зоны и YouTube
  остаются на полной скорости локального канала).

ECH-политика: расширение 0xfe0d/0xff0d с payload 1 байт — это GREASE-пустышка
(клиенты шлют её почти на каждый CH) и ECH не считается. Настоящий ECH
(payload > 1 байта) ТСПУ дропает — такие потоки принудительно в TUNNEL.

Fallback-цепочка DESYNC: если пробить не удалось — TUNNEL; туннель мёртв —
деградация в DEGRADED с перекалибровкой. Все переходы в лог.

## 5.1 Быстрый старт и профиль калибровки

Первый запуск без профиля: PROBING 2–4 минуты (классификация + лестница TTL с
анти-эскалационными паузами 4–8 с — ускорять нельзя, ТСПУ учится на сериях).

После успешной калибровки профиль (t*, margin, классификация, target-хосты,
timestamp) пишется в `%ProgramData%\rupas\profile.json`. Валидный профиль
(< 72 ч) даёт **OFF → ACTIVE за ~2 секунды**, дальше идёт фоновая ревалидация
одним пробом; провал ревалидации → штатная перекалибровка через DEGRADED.
Повторная калибровка при наличии профиля начинает лестницу с `t*±1`.

Пробы классификатора биндятся на физический NIC: при запущенном VPN-клиенте с
TUN пробы без биндинга уходят в туннель и дают ложное «sni blocked».


## 6. Платформенный стек

**Windows (MVP):** Go; WinDivert (драйвер подписан) для перехвата/инжекта;
sing-box lib; uTLS; GUI — Wails (лёгкий, нативный) или консоль+трей v0.
Требование: запуск без прав админа невозможен (драйвер) → установщик + сервис.

**Android (v2):** VpnService (один TUN на всё), netstack: TCP-потоки —
SNI-инспекция → desync (модификация CH в netstack + protect() прямых сокетов)
или перенаправление в sing-box lib; UDP Discord → XUDP через туннель.
Никаких root. Telegram: те же CIDR через туннель — в клиенте TG чисто.

## 7. MVP-скоуп (Windows, ~6–8 недель одного разработчика)

1. Ядро: WinDivert-слой + SNI-инспектор + rule-engine (конфиг YAML).
2. Desync: fake с калиброванным TTL + split. Браузер-валидация в прбах.
3. Telegram: перехват CIDR → локальный SOCKS → sing-box(VLESS-Reality) → VPS.
4. Probe-engine: классификация + TTL-калибровка + автопереключение.
5. CLI + кнопка ON/OFF + лог. GUI — после CLI-валидации.
6. Диагностика: отчёт «что видит ТСПУ» одной командой.

Вне MVP: Discord-голос через туннель (движок уже умеет — нужен только UX),
Android, автоматические обновления, community-списки.

## 8. Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| ТСПУ начнёт резать фейк-пакеты (детект повторов) | средняя | probe-engine перебирает split/disorder/multisplit; туннель как fallback уже в v1 |
| ECH-трафик не пробивается desync (подтверждено для Schannel) | высокая | (а) детект ECH → этот поток в туннель; (б) рекомендация отключить ECH-флаг браузера |
| WinDivert-драйвер: ложные срабатывания AV | средняя | подпись Eventually EV-сертификатом; документация для «своих» |
| Смена блок-политики на мобильных операторах (L4 не измерен) | высокая | probe-engine портативен; замер на телефоне — первый спринт Android |
| Лицензии: sing-box (GPL-совместимость проверить), WinDivert LGPL | низкая | динамическая линковка WinDivert; sing-box MIT — ок |

## 9. Roadmap

- **W1–2:** каркас ядра, WinDivert-инспекция, SNI-детект, CLI, конфиг.
- **W3–4:** desync (fake+split) + probe-калибровка TTL; браузер-валидация.
- **W5–6:** туннель TG (sing-box lib, VLESS-Reality), fallback-цепочка.
- **W7–8:** диагностика, стабилизация, «полевые» испытания на ISP юзера.
- **Далее:** Android-порт ядра (тот же Go), Discord-UDP через туннель, GUI.
