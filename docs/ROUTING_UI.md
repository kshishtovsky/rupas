# Маршрутизация — UX/UI-спецификация (Android + Windows)

Новая фича: экран, где владелец **видит и правит правила маршрутизации** без YAML, и может **проверить, куда уйдёт конкретный домен/IP**. Один информационный каркас, две платформенные реализации в существующей теме `dose`.

- Android: `RoutingActivity` (вход из Настроек)
- Windows: `#page-routing` + 4-й пункт навигации «Маршруты»

---

## 1. Проблема и цель

Сегодня правила живут только в `configs/rupas.yaml` (51 правило в боевом конфиге) и правятся руками либо через TUI `rupasctl`. Ни GUI, ни Android не умеют их показывать. Три реальных отказа, которые это производит:

1. **Утечка реального IP.** Пресет с `default: direct` = трафик на незнакомые dst идёт мимо туннеля. Диагностируется владельцем как «сайт отдаёт мой настоящий IP», а не как ошибка конфига.
2. **Невидимая семантика.** Резолвинг не является порядком списка: сначала CIDR, затем SNI, затем порты, затем default. Пользователь, который «переставил правило наверх», не изменил ничего — и не узнает об этом.
3. **Мёртвая правка.** Опечатка в CIDR/порте делает конфиг невалидным (`overlapping port spans`, `bad cidr`), демон не перезагружается, а UI молчит.

**Цель:** любой вопрос «почему этот трафик идёт туда» и любая правка политики — за один экран и один тап сохранения, без открытия YAML.

**Метрики успеха (проверяемые, не декоративные):**
- 0 невалидных конфигов, доходящих до `reload` (валидация в UI теми же функциями движка `config.Validate`).
- Ответ на «куда уйдёт `x.com`» — один ввод, один результат, без сохранения.
- Ни одного состояния экрана, где `default` не виден на экране вместе со своим действием.

## 2. Семантика движка = информационная архитектура

Это главный дизайн-факт, из него следует вся структура экрана. Источник: `internal/rules/compile.go`, `internal/rules/rules.go`, `internal/config/config.go:453`.

| Факт движка | Следствие для UI |
|---|---|
| Резолвинг фиксирован: **CIDR/geoip → SNI (exact → wildcard) → ports → default** | Экран сгруппирован по **стадиям**, а не плоским списком с drag-reorder |
| Внутри стадии на дубле ключа **побеждает первое правило** (`compile.go:146-158`, «on a shared prefix the first rule wins») | Порядок имеет смысл **только внутри стадии** → reorder разрешён внутри группы, между группами — нет |
| Пересечение портов = **ошибка компиляции** (`sortAndCheck`, `compile.go:130`) | Ввод порта валидируется на пересечение до сохранения, показывается конфликтующее правило |
| Одно правило = ровно один матчер (`at most one of cidr/sni/ports/geoip`) | В редакторе вид правила — взаимоисключающий селектор, не набор чекбоксов |
| Правило без матчера = **default** | Default — отдельная закреплённая зона внизу, не строка списка; удалить нельзя |
| `proto`: `""`/`tcp`/`udp` | Селектор протокола есть у всех видов; QUIC-блок (udp/443) — частая операция, поэтому вынесен в пресет |
| Действий ровно 4: DIRECT, TUNNEL, DESYNC, BLOCK | 4 сегмента действия, фиксированный цвет на каждое, без кастомных «уровней» |

**Стадии (они же секции экрана):**

1. **IP-адреса** — `cidr`, `geoip`
2. **Домены** — `sni` (exact), `sni` wildcard `*.suffix`
3. **Порты** — `ports`, `proto`
4. **Всё остальное** — `default` (закреплено, не сортируется)

Счётчик правил на каждой стадии + счётчик в шапке.

Все размеры — из `dimens.xml` (Android) и `theme.css :root` (Windows). Новых цветов **не вводится**.

### 5.2 Rule row
- Android: карточка `radius_card` 24dp, фон `paper_2`, `space_m` паддинг, min-height 64dp, вертикальные отступы между карточками `space_s` 12dp.
- Windows: строка-карточка `radius_panel` 20px, фон `--paper-2`, паддинг 12/16, min-height 56px, border `--rule`.
- Содержимое: 3 зоны.
  1. **Матчер** — значение как данные: `font-variant-numeric: tabular-nums` / `fontFamily="monospace"` (моно — материал здесь, Floor 64 разрешает), 14sp. Wildcard показывается как `*.googlevideo.com`, geoip — как `geoip: ru` + человеческая подпись «Категория RU».
  2. **Подпись** — второй строкой, 12sp `ink_soft`: для CIDR — сколько адресов покрыто (для `/23` = 512 адресов — считать, не выдумывать); для geoip — «таблица стран, обновляется раз в 30 дней»; для порта — диапазон человеческим текстом.

- Ручка перетаскивания (`≡`) слева, 44dp зона; видна всегда на Windows (плотность), на Android — по long-press (иначе визуальный шум).
- Overflow `⋮` → `Изменить`, `Дублировать`, `Удалить` (danger, если не default).
- **8 состояний:** normal · hover (только Windows) · focus-visible (кольцо `--focus` 2px, offset 2px, мгновенно) · pressed (`paper_3`) · selected (фон `accent_tint`, левая линия 3px `accent`) · dragging (тень, `opacity .96`, соседи сдвигаются `transform: translateY` 120ms) · disabled (только `ink_soft`, `ink_faint` — не текст) · error (левая линия `danger`, подпись с причиной).

### 5.4 Добавление/редактирование правила
- **Windows:** inline-панель, разворачивается под стадией (не модалка). Поля: вид (4 сегмента: `IP/CIDR` `Страна` `Домен` `Порт`), значение (один input с placeholder по виду), протокол (3 сегмента `любой/tcp/udp`, для `порт`+`любой` — предупреждение о QUIC), действие (4 сегмента). ### 5.5 Проверка маршрута (сигнатурный элемент)
Единственное, что владелец запомнит: **трасса решения**. Ввод домена или IP → карточка результата:
- строка 1: `стадия 2 · Домены`
- строка 2: `правило: *.googlevideo.com`
- строка 3: `DESYNC` чипом
- если совпадения не было: `стадия 4 · по умолчанию` + действие default + если default=DIRECT, строка `danger`: «IP не скрыт».
- пустой ввод → карточка не показывается (не рисуем пустое состояние проверки).
- ввод IP → стадии 1 и 3 участвуют, домены — нет (в результатах так и пишем: «домены не проверяются для IP»).
- ошибка ядра (`rules.test` недоступен) → `ink_soft` строка «проверка недоступна: демон не отвечает» + кнопка `Повторить`.

**Транспорт пробы (обязательно к исполнению).** Проба без протокола означает **TCP** — обычный веб-трафик. Иначе правило QUIC-блока (`udp/443 → BLOCK`) решало бы любую пробу и отвечало `BLOCK` на адреса, которые движок на самом деле туннелирует по TCP (проверено: `1.1.1.1` давал `BLOCK`). Для явной проверки UDP — суффикс: `1.2.3.4:443/udp`, `example.com:443/udp`. Голый IP без порта трактуется как `443/tcp` с пометкой «порт не указан — принят 443/tcp».

**Warning ≠ Note.** Замечание о самом наборе правил (например, geoip-таблица страны недоступна и правило не участвовало) приходит отдельным полем `warning`, а не в `note`: иначе оно украшает каждую пробу и превращается в шум. Показывается один раз под результатом приглушённой строкой `warn`: «<текст> — часть правил не проверена».

### 5.6 Пресеты
`Пресеты ▾` → список: `Политика владельца (51)` · `RU напрямую, остальное в туннель` · `Всё через туннель` · `Всё напрямую` (danger, требует подтверждения второй кнопкой: «Разрешить весь трафик мимо туннеля? IP будет виден»). Пресет заменяет правила целиком, помечает список dirty, применяется только по `Применить`.

### 5.7 Панель сохранения
Появляется при `dirty` (Android — снизу над навигацией, 52dp; Windows — бар внизу страницы). `Отменить` / `Применить правила`.
Семантика применения на платформах разная и должна быть сказана словами:
- Windows: `reload` демона, без разрыва соединений → подпись «Применится без разрыва».
- Android: ядро читает правила только при старте → подпись «VPN перезапустится (~2 с)»; после применения — `Применить` → core stop/start, статус-бар не мигает в «Ошибка» во время рестарта (guarded state).

## 7. Motion

`--dur-micro: 120ms` (сдвиг соседей при drag, чипы), `--dur-short: 180ms` (раскрытие секции, появление панели сохранения, полоска «Применено»). Только `transform` и `opacity`. Никаких `transition: all`, никакой анимации `width/height/top/left`. `prefers-reduced-motion: reduce` — всё кроме мгновенного переключения отключено. На Android — `ValueAnimator` с той же длительностью либо без анимации при `Settings.Global.ANIMATOR_DURATION_SCALE == 0`.

## 10. Контракт данных (для исполнителей)

Правило в YAML/JSON остаётся как есть: `{cidr, sni, ports, geoip, proto, action}` (одно из первых четырёх; пусто = default).

Новые API (ничего существующего не ломаем):

**Go — ядро (`internal/config`, `internal/rules`)**
- `config.ParseRulesJSON([]byte) ([]config.Rule, error)` — парсинг + `Validate` (переиспользовать `Config.Validate` через временную копию).
- `rules.TestRoute(rules []config.Rule, query string) (Trace, error)` — `Trace{Stage int, StageName, MatchedMatcher, Action, Note}`; для IP — стадии 1/3, для домена — 2.

**Демон (`internal/rpc/server.go`)** — команды: `rules` (вернуть JSON правил), `rules-set` (принять JSON, валидировать, записать конфиг, `reload`-семантика), `route-test <query>`.

**Windows-мост (`internal/guictrl`)**
- `LoadRules() (RulesView, error)` → `RulesView{Rules []RuleView, Default RuleView, Stages [3]int, Error string}`
- `SaveRules(jsonRules string) error`
- `TestRoute(query string) (string, error)` — JSON `Trace`
- `ApplyPreset(name string) error`

**Android-мост (`mobile/core.go`, `internal/transport/android`)**
- `RulesJSON() string`
- `SetRulesJSON(string) error` — принимает правила; применяются при следующем `Start` (текущая семантика ядра)
- `TestRoute(query string) string`
- `CompileRulesEx` получает источник правил из настроек вместо хардкод-пресета (пресет остаётся дефолтом, если правил не передали).

## 11. Приёмка

1. `go build -tags "with_utls with_quic" ./...` — зелёный.
2. `go test ./internal/rules/ ./internal/config/ ./internal/guictrl/` — зелёный; новые тесты: парсинг/валидация правил, `TestRoute` на всех 4 стадиях, отказ на пересечении портов.
3. `GOOS=android GOARCH=arm64 go build -tags "with_utls with_quic with_gvisor" ./mobile ./internal/transport/android` — зелёный.
4. Android: `gradlew assembleDebug` + установка `install -r`, экран открывается из Настроек, правка правила сохраняется, `Проверить` отвечает; скриншот экрана в 3 состояниях (full / empty / error) приложен.
5. Windows: страница доступна из навигации, `Проверить` отвечает на `youtube.com` → `DESYNC`, на `example.com` → default.
6. `staticcheck` по тронутым пакетам без новых находок.
7. Ни одного литерального цвета вне токенов; `ink_faint` не используется как цвет текста.
