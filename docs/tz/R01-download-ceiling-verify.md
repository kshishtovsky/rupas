# R01 — потолок download 20–21 Мбит/с: что уже исправлено и как это проверить

**Severity:** Critical (это и есть исходная жалоба)
**Репозиторий:** `E:/rupas`
**Слой:** userspace TCP-терминатор, направление «клиент ← мы»
**Статус:** код исправлен и закоммичен; требуется перезапуск демона и замер

## Диагноз (арифметика, не догадка)

Потолок задаёт не транспорт, а произведение «сколько байт в полёте × RTT»:

```
65535 Б × 8 / 0.025 с = 20.97 Мбит/с     ← ПК
1 МиБ   × 8 / 0.025 с = 335.5 Мбит/с     ← телефон
```

Обе цифры жалобы (20–21 Мбит/с на ПК, 300+ на телефоне) — это **одна формула
с разными окнами**. На ПК TCP терминирует `internal/tunnel/tcpterm.go`:
он подделывает SYN-ACK. Если в SYN-ACK нет опции Window Scale, клиент Windows
по RFC 7323 §2.2 **обязан** слать несмасштабированное окно, то есть максимум
65 535 байт — и получает ровно 21 Мбит/с при 25 мс.

На телефоне TCP терминируется внутри приложения (gvisor/sing-tun) со своим
окном — отсюда 300+.

```bash
cd /e/rupas && git log --oneline -2
grep -n "WS kind" internal/tunnel/tcpterm.go   # опция объявляется в craft()
go test -tags "with_utls with_quic" -run TestSynAckCarriesWindowScale -v ./internal/tunnel/
```

## Что осталось сделать руками (это не код)

1. **Собрать заново и перезапустить демон.** Автозапуск указывает на
   `E:\rupas\build\rupas-gui.exe` (HKCU Run), а демон поднимает GUI. Пока
   процесс `rupasd.exe` не перезапущен, в памяти живёт старая сборка с прежней
   логикой окна.

```bash
cd /e/rupas && mingw32-make build gui
taskkill //IM rupas-gui.exe //F ; taskkill //IM rupasd.exe //F
```

2. **Проверить, что WS реально в SYN-ACK** (30 секунд, Wireshark на ПК):

```
tcp.flags.syn == 1 && tcp.flags.ack == 1
```
В Options первого SYN-ACK от «сервера» должна быть строка
`Window Scale: 0 (multiply by 1)` **нашей** стороны и сдвиг клиента — в его
SYN. Отсутствие опции = старая сборка.

3. **Замер.** Cloudflare Speed Test, тот же сервер, что давал 21 Мбит/с.
   Ожидание: потолок уходит, скорость определяется каналом.

4. **Если 21 Мбит/с осталось** — следующий подозреваемый уже другой:
   `R02` (наше приёмное окно 64 КиБ, это upload) либо окно самого носителя
   (TCP до VPS). Проверять так: `curl` через локальный SOCKS/прокси tmnc
   мимо терминатора; если там 100+ Мбит/с — виноват терминатор, если тоже
   ~21 — виноват канал/носитель, а не rupas.

## Критерий закрытия

Замер Cloudflare ≥ 100 Мбит/с на ПК при том же сервере ИЛИ подтверждённый
Wireshark-ом WS в SYN-ACK + отсутствие потолка на 2–3 разных серверах.
